# Интерактивная карта районов и участков

В комплекте:

- `index.html` — готовая карта на Yandex Maps JavaScript API v3;
- `areas.geojson` — реальные полигоны, преобразованные из файла `Дворы_САО_уникальные_цвета_участков.kml`.

## Что уже реализовано

- API-ключ добавлен в подключение Yandex Maps JS API v3;
- цвет определяется по двум полям: `district` и `section`;
- легенда сгруппирована по районам;
- фильтры «Район» и «Участок»;
- клик по полигону показывает сведения об объекте;
- поддерживаются `Polygon` и `MultiPolygon`;
- можно загрузить GeoJSON через кнопку «Загрузить GeoJSON» без изменения кода;
- если `areas.geojson` не найден, показываются 4 встроенных демонстрационных полигона.

В текущем `areas.geojson` — 2 294 объекта по 16 районам САО. Объекты, у которых в KML было указано «не определён (нет в таблице раскрепления)», приведены к категории `Без участка` и отображаются серым цветом `#808080`.

## Дополнительные слои

Карта также загружает отдельными слоями:

- `mno.geojson` — 1 831 место накопления отходов;
- `dp.geojson` — 2 254 детские площадки;
- `sp.geojson` — 838 спортивных площадок;
- `smm.geojson` — 3 эталонных дворовых территории с маршрутами СММ. Два контура подтверждены действующим реестром дворов; для ДТ-2 требуется адресная сверка (в реестре указан дом 30Б, в схеме — дом 30).

Слои включаются и выключаются в боковой панели. Для всех слоев работают фильтры по району и участку, а клик по точке или полигону показывает карточку объекта. Исходные строки без корректных координат в публикацию не включаются.

## Как запустить

1. Сохраните оба файла в одну папку.
2. В кабинете Yandex Developer добавьте ограничение ключа по HTTP Referer:
   - для локальной проверки: `http://localhost:8000/*`;
   - для рабочего сайта: адрес вашего домена, например `https://example.ru/*`.
3. В этой папке запустите локальный сервер:

   ```bash
   python3 -m http.server 8000
   ```

4. Откройте в браузере `http://localhost:8000/`.

Открывать `index.html` двойным щелчком как `file://...` нежелательно: браузер может запретить загрузку `areas.geojson`, а ключ JS API v3 работает только с корректным HTTP Referer.

## Формат реального GeoJSON

Каждый полигон должен быть отдельным объектом `Feature`, а его свойства должны содержать район и участок:

```json
{
  "type": "Feature",
  "id": "voikovsky-1",
  "properties": {
    "district": "Войковский",
    "section": "Участок 1",
    "name": "Место накопления отходов № 1",
    "address": "Москва, пример"
  },
  "geometry": {
    "type": "Polygon",
    "coordinates": [
      [[37.48, 55.85], [37.49, 55.85], [37.49, 55.84], [37.48, 55.84], [37.48, 55.85]]
    ]
  }
}
```

Важно: в GeoJSON порядок координат — `[долгота, широта]`, то есть `[lng, lat]`. Для нескольких объектов используйте `FeatureCollection`:

```json
{
  "type": "FeatureCollection",
  "features": [
    { "type": "Feature", "properties": { "district": "Войковский", "section": "Участок 1" }, "geometry": { "type": "Polygon", "coordinates": [] } }
  ]
}
```

## Как использовать данные из карты Конструктора или KML

Ссылка вида `yandex.ru/maps/?um=constructor:...` — это ссылка на готовую карту Конструктора, а не GeoJSON-файл. JS API не получает из нее список полигонов и их координаты.

Поэтому есть два рабочих варианта:

1. получить координаты границ из исходного проекта/ГИС и сохранить их в GeoJSON;
2. заново обвести границы в любом редакторе GeoJSON, например geojson.io, затем добавить свойства `district` и `section`.

В текущем комплекте KML уже преобразован в `areas.geojson`. Если появится новая выгрузка, замените содержимое `areas.geojson` или загрузите новый файл через кнопку в интерфейсе.

## Как поменять цвета

В `index.html` найдите объект `COLOR_LEGEND`. Формат записи:

```js
'Войковский': {
  'Участок 1': ['#2263CE', 'синевато-голубой']
}
```

Первое значение — цвет заливки, второе — подпись в легенде. Для незаполненного участка используется серый `#808080`.

## Публикация на сайте

Загрузите `index.html` и `areas.geojson` на любой обычный веб-хостинг. В настройках API-ключа укажите HTTP Referer рабочего домена. Если карта размещается внутри CMS, обычно достаточно вставить содержимое `body` и скрипт из `head`, но безопаснее разместить готовый файл как отдельную страницу.
