# Потоковые резервные копии САО

С 9 ноября 2026 полные временные дампы и архивы на корневом диске не нужны:
`pg_dump -Fc / tar → age → rclone rcat → Google Drive`.
На сервере остаются JSON-отчёты; буферы ограничены размером чанков, снимки
между собой сериализованы файлом `server-backups/backup.lock`.

Текущий адрес: `gdrive:SAO-backups/stream-v1/{database,media}/<UTC timestamp>`.
Ключ шифрования и учётные данные Drive те же, что у прежних копий.
Предыдущие локальные и облачные копии не удаляются. Новая версия намеренно
не запускает прежний `sao-offsite.sh run`: его очистка рассчитана на старый формат.
Автоматического удаления новых потоковых копий в этой версии нет; следить
за квотой Drive отдельно. Проверено при включении: свободно около 4,07 ТиБ.

## Целостность и границы

- Каждый компонент зашифрован отдельно; точный размер, MD5 и SHA-256 потока
  записываются в манифест. Размер и MD5 сверяются с метаданными Drive.
- Для каждого исходного дампа проверяется каталог `pg_restore --list`.
  Это не полный тест восстановления строк и не расшифровка облачной копии.
- Неуспешный producer, age, validator или upload отклоняет всю копию.
  В неполной облачной папке может остаться файл, но нет `result.json`.
- `result.json` записывается последним и сверяется на Drive. Только после
  этого обновляется локальный `stream-latest-<kind>.json`.
- Каждая БД согласована отдельно, единого атомарного снимка всех сервисов
  нет. Файлы медиа копируются онлайн. Во время копии не запускать очистку фото.
- Облачные снимки ещё не протестированы полным восстановлением с приватным
  ключом age: приватный ключ для этого в рамках задачи не запрашивался.

## Включение

Файл `stream_backup.py` установлен как
`/opt/sao-recovery/stream_backup.py`, mode 0700.
Таймеры и исходные скрипты сохранены. Для трёх существующих служб добавлены
`/etc/systemd/system/<service>.service.d/stream-v1.conf`:

```ini
[Service]
ExecStart=
ExecStart=/usr/bin/python3 /opt/sao-recovery/stream_backup.py database
TimeoutStartSec=21600
UMask=0077
Environment=PYTHONUNBUFFERED=1
```

Для `sao-backup-media.service` аргумент `media`, для `sao-offsite.service` —
`verify`. Старая очередь в `sao-offsite.sh` больше не загружает устаревшие
архивы вместо свежих. Запуск вручную:

```bash
systemctl start --no-block sao-backup-database.service sao-backup-media.service
journalctl -u sao-backup-database.service -u sao-backup-media.service -f
python3 /opt/sao-recovery/stream_backup.py verify
```

`verify` сверяет компоненты последней завершённой пары копий с Drive;
отсутствующий манифест — ошибка. Возраст копий следует проверять по
`created_at`: совпадение хэшей само по себе не означает свежую копию.

Небольшая проверка без перезаписи production-данных:

```bash
python3 /opt/sao-recovery/stream_backup.py smoke
```

Она читает базу «Люков» и конфигурации, сохраняет отдельную облачную папку
`stream-v1/smoke`. Включение 9 ноября подтверждено успешной пробной копией.

## Восстановление: сначала изолированная проверка

Получить путь компонента и контрольные суммы из завершённого `result.json`.
Приватный ключ age брать из существующего защищённого хранилища, не из чата.
Сначала проверить расшифровку и каталог без записи в рабочую БД:

```bash
set -o pipefail
rclone cat 'gdrive:SAO-backups/stream-v1/database/<stamp>/photo.dump.age' |
  age -d -i /secure/backup-identity.txt |
  docker exec -i sao-photo-service-database-1 pg_restore --list
```

При полном восстановлении применять дамп в отдельную тестовую БД подходящей
версии PostgreSQL. В production направлять только после проверки результата
и отдельного решения. Медиа проверять потоковым `tar -tf -`, затем извлекать
в отдельную пустую staging-папку; не распаковывать сразу в `/`.
Конфигурации могут содержать секреты: только закрытая папка с правами 0700.

## Откат

Дождаться завершения текущих заданий либо штатно остановить только задания
бэкапа. Удалить исключительно созданные `stream-v1.conf` из трёх drop-in
каталогов, выполнить `systemctl daemon-reload`.
Это вернёт прежние ExecStart. Старые скрипты и копии не перезаписывались.
При свободных 21 ГБ прежняя схема снова не сможет создавать полные копии:
откат не решает нехватку диска.
