# Google-таблица проверки пешеходных дорожек

Статус на 11.11.2026: серверный срез, превью по токену, решения, шаблон Apps Script
и тесты подготовлены. Книгу нужно один раз создать в Google и вставить шаблон —
доступ к аккаунту Google агент не запрашивает.

## 1. Что получится

- **«Реестр»** — 12 888 точек съёмки: район, адрес, номер точки, ID дорожки,
  длина трассы, площадь, покрытие, координаты, статус, фото, даты, решение.
- **«Свод»** — 16 районов: всего, без фото, принято, на проверке, на доработке,
  «% принято». Колонка «% принято» красится: 100 % — зелёный, 80–60 % — жёлтые
  оттенки, ниже — красные.
- **«На доработке»** — возвращённые точки с причиной и ссылкой на карту.
- **«Журнал»** — когда и сколько строк обновилось, ошибки.

Таблица обновляется каждые 10 минут. После первого полного среза сервер отдаёт
только изменившиеся строки, поэтому обновление не упирается в суточный лимит
Apps Script. Если данные выглядят устаревшими, в меню есть «Полная пересборка».
Решения отправляются в кабинет: «Принять» принимает ожидающий кадр, «Проверено» отмечает уже принятый,
«Вернуть на доработку» реально отзывает снимок. Решение адресуется `photo_id`,
поэтому строка, устаревшая после пересъёмки, не тронет новый кадр.

## 2. Создание книги

1. Открыть <https://sheets.new>. Назвать, например,
   «Пешеходные дорожки САО — приёмка».
2. «Расширения» → «Apps Script».
3. Удалить заготовку `Код.gs` и вставить целиком
   `dev/templates/pedestrian-path-sheet.gs`.
4. Слева «Настройки проекта» → «Свойства скрипта» → «Добавить свойство»:
   - `SAO_TOKEN` = токен служебной учётной записи фотослужбы.
     Токен выдаёт администратор службы; в ячейки и в git его не кладут.
5. Сохранить, перезагрузить таблицу. Появится меню **«Дорожки»**.
6. «Дорожки» → **«Настроить книгу»**. Скрипт создаст листы, шапки, фильтр,
   проверку ввода и условное форматирование.
7. «Дорожки» → **«Обновить сейчас»**. В «Реестре» появятся 12 888 строк.
8. «Дорожки» → **«Включить автообновление (10 мин)»**.

Если книга уже была с данными, «Настроить книгу» не очищает строки: она только
создаёт недостающие листы и обновляет оформление.

## 3. Решения

В «Реестре» колонки:

| Колонка | Что это |
|---|---|
| R | Решение: `Принять`, `Проверено`, `Вернуть на доработку` |
| S | Причина возврата (обязательна для возврата, если T пуст) |
| T | Комментарий проверки |
| U | Отправлено: `OK` или текст ошибки |
| V, W | Скрытые `photo_id` и `point_id` — не удалять |

После заполнения R:T нажать «Дорожки» → «Отправить решения» (или подождать
10 минут). Повторная отправка того же решения ничего не меняет.

- **Принять** — только для строки «На проверке». Снимок становится принятым.
- **Проверено** — только для строки «Принято». Меняет только журнал.
- **Вернуть на доработку** — для «На проверке» или «Принято». Снимок становится
  отклонённым, точка возвращается в «На доработке» кабинета.

При правке R:T отметка U очищается автоматически, поэтому решение можно
исправить и отправить заново. Если решение уже применено, а фото пересняли,
старая строка получит `photo_not_pending` / `photo_not_active` — новый кадр
не пострадает.

## 4. Проверка после установки

- [ ] В «Реестре» 12 888 строк, шапка закреплена, фильтр работает.
- [ ] В «Своде» сумма по районам равна 12 888.
- [ ] В колонке «Фото» пусто, пока нет снимков; после загрузки появляется превью.
- [ ] «% принято» красится: 100 % — зелёный, 80–60 % — жёлтые, ниже — красные.
- [ ] «На доработке» показывает возвращённые точки и причину.
- [ ] В «Журнале» последняя строка `sync ... OK`.
- [ ] «Отправить решения» на тестовой строке даёт `OK`, статус меняется.

## 5. Если что-то не так

| Симптом | Что проверить |
|---|---|
| `Не задан SAO_TOKEN` | Свойства скрипта, имя свойства, сохранение |
| `HTTP 401` | Токен отозван или это токен другой службы |
| `HTTP 403` | Учётка не префектура |
| Пустые строки | Запустить «Обновить сейчас», смотреть «Журнал» |
| Превью не грузится | Проверить, что `photo_token` есть в `/sheet.json`; Google может кэшировать `=IMAGE()` до суток |
| Формулы с `;` не работают | Скрипт сам определяет разделитель по локали книги; вручную ничего менять не нужно |
| Решение не уходит | U уже заполнено — очистить U или изменить R:T (onEdit очистит сам) |

## 6. Серверная часть

- `GET /object-photo-points/pedestrian-path-sheet/sheet.json` — срез, только префектура.
- `GET /object-photo-points/pedestrian-path-sheet/photo-thumb/<token>` — превью 320 px,
  без сессии: `=IMAGE()` не умеет `Authorization`. Токен неугадываемый, отзываемый.
- `POST /object-photo-points/pedestrian-path-sheet/sheet-decisions` — решения,
  идемпотентно по `client_id`, журнал в `pedestrian_path_sheet_reviews`.
- Миграция `031_pedestrian_path_sheet.sql`.
- Код: `photo-service/src/tpu-points/pedestrian-path-sheet.js`.
- Тесты: `photo-service/test/pedestrian-path-sheet.test.js`.

## 7. Границы

- Книга не создаётся автоматически: для этого нужен доступ к Google-аккаунту.
  Шаблон и серверная часть готовы; установка занимает 5–7 минут по разделу 2.
- Токен служебной учётки хранится в свойствах Apps Script, а не в ячейке.
  Доступ к книге выдавать группе префектуры, не «всем, у кого есть ссылка».
- 12 888 строк — большой лист. Если книга начнёт открываться медленно,
  обновление можно перевести на 30 минут или разбить «Реестр» по районам;
  серверный срез от этого не меняется.
