# Оповещения в Telegram

Сервис присылает в Telegram отчёты о работе, события сервисов и ошибки, задаёт
вопросы с кнопками и выполняет действия после подтверждения.

## Что приходит в чат

| Вид | Что это | Пример |
| --- | --- | --- |
| 🤖 Работа агента | отчёт о выполненной работе | «Аудит карт завершён, 5 исправлений, тесты зелёные» |
| 👤 Работа пользователя | действия районов и префектуры | «Новое фото от района Аэропорт», «Префектура отклонила фото» |
| ❓ Вопрос | вопрос с вариантами ответа | «Обновлять зависимости?» — кнопки «Да» / «Нет» |
| ✅ Подтверждение действия | действие выполняется после нажатия кнопки | «Утвердить набор правок: Аэропорт» |
| 🔥 Ошибка | сбои сервисов | «Сбой обработки запроса: …» |

Ответы и решения попадают в журнал: `data/journal.jsonl`.

## Настройка

1. В Telegram открыть **@BotFather**, команда `/newbot`, задать имя — получить токен.
2. Узнать свой номер чата у **@userinfobot** (или у бота `@getmyid_bot`).
3. Заполнить `.env` по образцу `.env.example`:

```bash
TELEGRAM_BOT_TOKEN=123456:AA...
TELEGRAM_CHAT_IDS=123456789
NOTIFY_SECRET=длинная-случайная-строка
```

4. Запустить сервис и написать боту `/start`.

Свой чат должен быть в `TELEGRAM_CHAT_IDS`: сообщения из чужих чатов бот игнорирует,
а события принимаются только с секретом `NOTIFY_SECRET`.

## Запуск

```bash
# локально
node src/server.js

# на сервере, рядом с остальными сервисами
cd /opt/odh-sao
docker compose -f docker-compose.production.yml up -d --build notify
docker compose -f docker-compose.production.yml logs -f notify
```

## Отправка из командной строки

```bash
# отчёт о работе
node bin/notify.js event --kind agent --title "Аудит карт завершён" \
  --text "5 исправлений, тесты зелёные" --field "Коммит=f39ad5e"

# вопрос с ожиданием ответа
node bin/notify.js ask --text "Перезапускать сервис?" \
  --option "Да=yes" --option "Нет=no" --wait

# подтверждение действия
node bin/notify.js action --name submission.approve --title "Утвердить набор" \
  --submission <uuid> --wait

# состояние
node bin/notify.js status
```

Команды читают `NOTIFY_URL` и `NOTIFY_SECRET`. Если задан только
`TELEGRAM_BOT_TOKEN`, команда `event` отправит сообщение напрямую.

## Приём событий от сервисов

```http
POST /event    { "kind": "client", "title": "…", "text": "…", "fields": { "Район": "Аэропорт" } }
POST /ask      { "question": "…", "options": [ { "text": "Да", "value": "yes" } ] }
POST /action   { "name": "submission.approve", "title": "…", "payload": { "submissionId": "…" } }
GET  /pending  — что ждёт ответа
GET  /health   — живость сервиса
```

Заголовок `X-Notify-Secret` обязателен, если задан `NOTIFY_SECRET`.

Готовые клиенты уже подключены:

* `api/lib/notify.js` — карта ОДХ: новый набор правок приходит с кнопками
  «Утвердить» / «Отклонить»;
* `photo-service/src/notify.js` — фотослужба: новое фото, решение префектуры,
  сбой обработки запроса.

Сервисы шлют события «выстрелил и забыл»: недоступный бот не влияет на их работу.

## Разрешённые действия

Список действий закрыт и лежит в `src/actions.js`:

* `submission.approve` — утвердить набор правок района;
* `submission.reject` — отклонить набор правок района.

Каждое действие выполняется только после нажатия кнопки в разрешённом чате и
записывается в журнал вместе с тем, кто подтвердил.
