# Карта ОДХ САО

Публичная интерактивная карта: <https://hainox.github.io/karta-sao/odh-map/>.

## Содержание карты

- 688 уникальных объектов ОДХ: 98 в первой очереди, 318 во второй и 272 в третьей;
- граница САО и отдельная врезка Молжаниновского района;
- 215 точек привязки контейнеров ПГМ (451 контейнер), 24 кандидата на временное складирование снега и 3 сухие свалки;
- 20 подтверждённых учреждений здравоохранения и 1 адрес на уточнении;
- 402 места хранения СММ и 24 адресных центроида пожарных гидрантов.

Очередности считаются по уникальным ID ОДХ; в GeoJSON одна позиция может состоять из нескольких геометрических частей. Поэтому число объектов не равно числу GeoJSON features.

## Выгрузки

Раздел «Выгрузки» в сайдбаре карты собирает файлы прямо в браузере из уже
загруженных слоёв: сервер и вход не нужны, а числа совпадают с картой.

- `Excel: полный реестр` — книга `sao-odh-register.xlsx`: «Обзор», «На штаб»,
  «Районы» и лист на каждый слой с полными атрибутами источника;
- `Excel: таблица на штаб` — книга `sao-odh-headquarters.xlsx` из одного листа;
- `PDF: таблица на штаб` — печатная форма, из неё браузер сохраняет PDF;
- `CSV: объекты ОДХ по районам` — `sao-odh-objekty-<дата>.csv` по районам:
  объекты, точки, очереди и площадь уборки.

Единица счёта — точка, то есть геометрическая часть объекта: у одной позиции ОДХ
их бывает несколько. Рядом показывается вторая единица — объекты по ID.
Колонка «Факт» считает точки, подтверждённые официальным источником, а не просто
нанесённые на карту. Разбор по районам идёт по балансодержателю; объекты «АвД САО»
и объекты без района собраны в строке «АвД САО».

Логика выгрузок вынесена в `exports.js` (`window.ODHExports`) — чистый модуль без
DOM и сети, проверяется тестом `tests/exports.spec.js`. Книгу Excel собирает
ExcelJS, подключённый с CDN.

## Объекты районов из сервиса ОДХ

Нарисованное районами живёт не в слоях карты, а в единой базе, поэтому в сводку
на штаб его добавляет раздел «Объекты районов»: соединение с сервисом
(`odh-map/api-config.js`, по умолчанию `https://obhod-sao.ru/odh-api`), вход
учётной записью префектуры и загрузка `GET /api/submissions`.

Загруженные наборы попадают в «На штаб» отдельной таблицей — по районам:
маршруты уборки, роторные перекидки, прочие объекты, всего, на приёмке,
утверждено, отклонено и время последней отправки. Ниже строки «ИТОГО» идёт строка
«Без объектов (N): …» со списком районов, которые ничего не прислали. Пока данные
не загружены, блок остаётся на листе с пометкой «данные единой базы не
загружены»: пустое место читалось бы как «районы ничего не прислали».

- **Маршруты уборки и роторные перекидки** считаются отдельными колонками —
  это приоритет заказчика. Остальные девять типов сворачиваются в «Прочие
  объекты», а их состав перечисляется в примечании под таблицей, иначе свёрнутая
  колонка читалась бы как загадка.
- **Типы берутся из `district-changes.js`** — одного словаря на редактор района,
  приёмку и эту выгрузку. Незнакомый тип не пропадает: он попадёт в «Прочие
  объекты» под своим ключом.
- **«Всего» сходится со сводкой службы.** Считаются все объекты всех наборов,
  независимо от статуса приёмки, поэтому сумма равна «Маршрутов» + «Зон» +
  «Точек» в отчёте `/api/reports/routes` — той самой сводке, что уходит в
  Telegram. Колонки приёмки здесь считают все объекты набора, а в сводке службы —
  только маршруты: числа в этих колонках больше, и примечание это объясняет.

Кнопка `CSV: маршруты районов (сервис)` отдаёт файл службы как есть —
`odh-routes-<дата>.csv` с приёмкой. У выгрузки объектов ОДХ имя другое
(`sao-odh-objekty-<дата>.csv`), потому что это другой отчёт: один считает
нарисованное районами, другой — объекты на опубликованной карте.

Кнопка `Excel: маршруты на штаб` собирает книгу `odh-routes-na-shtab-<дата>.xlsx`
в форме листа «На штаб» из выгрузок фотофиксации: блоки «Маршруты», «Зоны» и
«Точки» по «Объекты | Факт | %», сверху справочник районов, снизу та же таблица
по «Итого: %», светофор и комментарий для рассылки. «Объекты» — сколько объектов
района нарисовали и отправили, «Факт» — сколько из них утверждено приёмкой;
состояния приёмки (на приёмке, утверждено, отклонено) названы строкой в
комментарии, потому что в сетку эталона не помещаются. Числа считаются в момент
нажатия из загруженных наборов, поэтому книга всегда на текущих данных.

Данные единой базы доступны только роли `prefecture_admin`; ответы службы
отдаются с `Access-Control-Allow-Origin: https://hainox.github.io`, поэтому
запрос идёт напрямую из браузера.

## Районная разметка и печать

- `district-links.html` — вход по району;
- `district-editor.html` — разметка маршрутов и объектов;
- `district-review.html` — проверка и приёмка правок;
- `prefecture-guide.html` — памятка для приёмки;
- `print-a3.html` и `print-a1.html` — формы печати A3 и A1; карта также содержит отдельный лист `print-1000x1400.html`.

Правки становятся частью утверждённой карты только после проверки и приёмки. Локальный просмотр файла сам по себе ничего не публикует.

Готовые GeoJSON-слои, которые загружаются опубликованной картой, находятся в `layers/`. Исходные таблицы, рабочие материалы и код подготовки выгрузок лежат в `projects/odh-yandex-export/` и не входят в GitHub Pages.

Счётчики сверены с опубликованной интерактивной картой и слоями 14 сентября 2026 года.
