# Мобильные кабинеты ДП/СП и МАФ — подготовка

Дата: 17.11.2026. Статус: проектирование, production не изменён.

Основной документ: `../../dev/BuildSpec-Mobile-Cabinets-20261117.md` — черновик для утверждения, не замена существующего BuildSpec по тротуарам.

## Что проверено

- Просмотрены реальные снимки оцифровки на телефоне и ПК и приёмки принятого тестового объекта, расположенные в соседнем `../dpsp-browser-20261117/`.
- Прочитан текущий серверный `dp-sp-cabinet/cabinet.css`. Сохранение существующей зелёной палитры — часть предлагаемого объёма.
- Выявлены подтверждённые визуальные проблемы: карточка открывается ниже очереди; фильтры занимают значительную часть мобильного экрана; выбор файла МАФ не помещается в узкой колонке.
- Через Supericons найдены и сохранены десять реальных SVG единой семьи Lucide. Их происхождение и назначение — `icons/manifest.json`. Лицензия — `icons/LICENSE-source.md`, исходная официальная страница `https://lucide.dev/license`.
- Product Design preflight не обнаружил сохранённого пользовательского контекста; использован текущий бриф и реальные снимки проекта.

## Предлагаемая основа

Оба кабинета на телефоне: список площадок → отдельная карточка с началом у верхней границы экрана → возврат с сохранением фильтров и позиции списка. В карточке оцифровки — новые обзорные фото и МАФ с фото; в приёмке — просмотр этих материалов, принятие или возврат с обязательной причиной. На ПК сохраняется две колонки.

Это рекомендуется как наименьшая достаточная переработка. Дополнительные функции, новые сущности, offline-режим, автосохранение черновика и новые права доступа не вводятся.

## Что ещё необходимо

- Три независимых визуальных концепта созданы и показаны в основном чате; concept-1.png, concept-2.png и concept-3.png сохраняют порядок показа. Ожидаются выбор пользователя и утверждение конкретного BuildSpec.
- Свежая отдельная рабочая копия репозитория перед реализацией. Доступный локальный каталог `karta-sao` является старым зеркалом без git и не используется как основа выпуска.
- После реализации: мобильные проверки 360/390/430, планшет768, ПК1280, ошибки/права/повторные действия; камера и галерея на реальных Android/iPhone.

## Ограничения подтверждений

Наличие CSS и снимков не означает, что мобильная версия реализована или прошла аппаратное тестирование. На принятом тестовом объекте кнопки решения уже отсутствуют, поэтому их мобильное состояние этим снимком не проверено. Независимый основной агент завершает функциональную проверку цикла; в этот отчёт её результаты не перенесены без подтверждения.

Файлы продукта и данные production в этой задаче не изменялись. Автоматические тесты продукта не запускались, поскольку реализации пока нет.
