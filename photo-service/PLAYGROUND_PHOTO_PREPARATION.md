# Новый фотослой ДП/СП — черновик

Ветка готовит отдельные таблицы, импорт, API, слой на 16 картах и карточку одного фотослота. Не развёрнуто: требуется проверить настоящую PostgreSQL и связку на тестовом окружении.

Источник — districts/layers/{район}/dp_table.geojson и sp_table.geojson. 3 042 точки: 2 218 ДП и 824 СП. Восемь строк таблицы без координат отсутствуют в исходных слоях; два повторяющихся ID хранятся как отдельные строки. Ключ состоит из района и номера записи в таблице; при новой выгрузке надо отдельно проверить стабильность номеров. Две точки вне границы указанного района следует проверить.

Миграция 019 создаёт отдельные таблицы и уникальный индекс одного активного фото, не меняя районные точки и фотографии. API использует авторизацию фотослужбы, ограничивает район и проверяет формат/размер файла. Повторный импорт добавляет отсутствующие записи, не перезаписывает координаты и фото.

Сухой прогон: node scripts/import-playground-photo-points.js --source=/path/to/districts/layers
--apply применяет импорт в транзакции и создаёт по одному слоту. В контейнере каталог districts/layers требуется отдельно примонтировать с доступом только на чтение; стандартный архив photo-service его не содержит.

Тесты: node --test test/playground-seed.test.js test/playground-photo-api.test.js test/playground-photo-ui.test.js. Пройдены тесты с имитацией хранилища и интерфейса; отдельное испытание на PostgreSQL, реальная авторизация, отправка фото, восстановленная база и мобильная карта ещё не проверены.

Применять миграцию и импорт в production только после проверок и резервного копирования. Production запускается с compose.yaml и compose.recovery.yaml, как указано в deploy/SAO_PHOTO_PRODUCTION_RUNBOOK.md.
