# Подготовка отдельной фотофиксации площадок

Ветка содержит только основу БД и импортера. API, отдельный слой на картах, приёмка фото и отчёты ещё не подключены, изменения не готовы к развёртыванию.

Данные источника: districts/layers/{район}/dp_table.geojson и sp_table.geojson. Сухой импорт рассчитывает 3 042 записи (2 218 ДП, 824 СП), каждой соответствует один слот. Восемь строк исходной таблицы без координат в слоях отсутствуют. Два повторяющихся ID сохраняются как разные строки, ключ использует район и номер записи из исходного файла; при замене таблицы следует проверить неизменность этих номеров. Две точки за границей указанного района требуют проверки.

Миграция создаёт отдельные таблицы, не меняет существующие точки и фото. Фотографии имеют историю; уникальный индекс не допускает более одной действующей фотографии на слот.

Сухая проверка в photo-service: node scripts/import-playground-photo-points.js
ВНИМАНИЕ: применять миграцию и запускать с --apply только после готовности API, интерфейса, тестов PostgreSQL и сверки с продакшеном. --apply не обновляет существующие координаты и описания и не удаляет данные. Импорт обёрнут в транзакцию.

Тесты: node --test test/playground-seed.test.js
