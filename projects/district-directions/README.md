# Направления съёмки на районных картах

Источник: предоставленный пользователем «Ракурсы_180.geojson», 87 точек с `fid` и `azimuth`. Исходник сохранён в `work/` без изменений, его SHA-256 записан в `districts/directions/manifest.json`.

Координаты в источнике — EPSG:3395. Импорт пересчитывает их в WGS84 с порядком longitude, latitude, определяет район попаданием в опубликованный полигон `districts/layers/<slug>/boundary.geojson`. Неоднозначные, повторные и не попавшие ни в один район точки останавливают импорт. Значение `azimuth` сохраняется: 0° — север, положительное направление по часовой стрелке; название файла не используется для дополнительного разворота.

Результат: Восточное Дегунино — 68, Бескудниковский — 19. Слой включён по умолчанию только на картах с точками; имеет собственную галочку и карточки. Это статические направления, они не создают назначений и слотов фотослужбы.

Повторить импорт из корня проекта: `python projects/district-directions/work/import_directions.py`. Нужны `pyproj` и `shapely` (они используются в географических сборщиках проекта). Шаблон районных страниц — `work/district_page_template.html`, подключение сохраняется при `write_pages` в `work/build_district_layer_maps.py`.

Проверки: `python -m pytest tests -q`; `npm run test:ui -- tests/district-directions.spec.js` в `odh-map/`. Браузерный тест использует замену SDK для независимой проверки элементов и переключателя; реальная подложка проверяется отдельно скриптом `work/check_live_directions.mjs`.

Размер стрелок изменяется через `YMapListener.onUpdate` по `location.zoom`: на zoom 14 — 25% полного размера, zoom 16 — 50%, zoom 18 и ближе — 100%; минимум 18%. Масштаб и поворот выполняются относительно основания стрелки, поэтому её координата остаётся неподвижной.

Выходные координаты округлены до 9 знаков после запятой (субмиллиметровая точность): это устраняет различия последних разрядов при пересборке в PROJ на Windows и Linux. Контроль обратного преобразования — не более 1 мм в системе источника.

## Корректировка префектурой

Войдите учётной записью префектуры и включите «Корректировать стрелки». Перетащите опорную точку — положение сохранится автоматически в общей базе. Чтобы изменить направление, откройте карточку стрелки и введите азимут либо нажмите «Указать направление на карте» и выберите сторону кликом по карте. Escape отменяет выбор стороны. Обе операции сохраняют одну версию положения и направления; при конфликте загружается актуальная версия.

Исходный GeoJSON не перезаписывается. Корректировки хранятся в таблице `district_direction_corrections`, миграция `016_district_direction_corrections.sql`. Публичный GET `/object-photo-points/directions/public?district=...` возвращает сохранённые корректировки; PATCH `/object-photo-points/directions/:fid` принимает longitude, latitude, azimuth и expectedVersion и доступен только префектуре. При обновлении проверяются ID, числовые значения и принадлежность точки исходному району. В аудит пишется `district_direction_corrected`.

При недоступности сервера отображается исходный слой с предупреждением; корректировка заблокирована до загрузки актуальных данных. После неудачного сохранения положение откатывается. Опорная точка рисуется отдельным элементом в начале координат маркера и не участвует в масштабировании/повороте SVG.
