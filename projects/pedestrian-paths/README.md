# Пешеходные дорожки АСУ ОДС

Слой дорожек и точки съёмки для раздела «Пешеходные дорожки» кабинета приёмки.

## Данные

Источник — реестр АСУ ОДС (`reestr-ogh.mos.ru`), тип «Пешеходная дорожка», только САО.
В слой входят оба типа территорий:

- `parent_type_id = 38` — улицы и дворы: 11 819 дорожек;
- `parent_type_id = 40` — скверы, бульвары, парки: 4 291 дорожка;
- итого **16 110 текущих дорожек** и **19 027 точек съёмки**;
- ещё **289 исторических путей** из старого слоя «Тропинки» добавлены только
  для отображения: они не покрыты текущими полигонами и отсутствуют в текущей
  выгрузке АСУ. В карточке у них источник «Тропинки · архив», точки съёмки для
  них не создаются. Всего в слое 16 399 полигонов.

Геометрия пересчитана из МСК-77 в WGS84. Район проставлен по центроиду полигона;
для объектов, уже опубликованных в слое «Тропинки», сохранён их район.

Прежний слой «Тропинки» содержит 16 331 объект. 289 из них не покрыты текущими
полигонами и добавлены как архивные; остальные совпали с текущими. 355 объектов,
наоборот, появились в АСУ после старого среза. Геометрия общих объектов совпадает
с точностью до сантиметров.

## Популярные дорожки

Отдельный слой «Самые проходные дорожки» — 498 дорожек, от 20 до 39 на район.
Рейтинг считает:

- ближайшие входы/станции метро и железной дороги;
- ближайшие автобусные и трамвайные остановки;
- подъезды в радиусе 150 м (вес зависит от этажности);
- магазины, школы, медучреждения и точки услуг.

Отбор идёт по оценке, но с прореживанием: не больше 4 дорожек на клетку 500 м
и не ближе 35 м друг к другу, чтобы охватить разные узлы, а не только один
самый плотный. На карте слой розовый; для популярных дорожек отдельно
показаны 857 точек съёмки из 19 027.

```powershell
python projects/pedestrian-paths/work/rank_popular_paths.py `
  --osm osm-poi-sao.json `
  --summary popular-summary.json `
  --apply
```

`--osm` — срез OpenStreetMap, запрос Overpass описан в шапке скрипта.
Без `--apply` скрипт только считает и пишет свод, файлы не меняет.

## Сборка слоя и точек

Слой собирается из двух выгрузок АСУ (parent_type 38 и 40) и раскладывается по
16 районам, затем `prepare_layer.py` строит точки съёмки:

```powershell
python projects/pedestrian-paths/work/prepare_layer.py `
  --source "C:\путь\к\по_районам" `
  --out photo-service/assets/pedestrian-paths

python projects/pedestrian-paths/work/add_archive_paths.py `
  --assets photo-service/assets/pedestrian-paths `
  --existing districts/layers
```

Скрипт пишет 16 файлов `<район>.geojson` для карт и `points.geojson` — точки съёмки.
Короткая дорожка (трасса меньше 100 м) получает одну точку, длинная — точки вдоль
кольца с шагом около 70 м, поднятые на гребень расстояний (середину дорожки).
После этого `add_archive_paths.py` добавляет в файлы районов исторические
изолированные пути из «Тропинок» (только отображение, без точек).

`photo-service/assets/pedestrian-paths/` в git не хранится: слой закрытый, его
отдаёт фотослужба только префектуре.

## Выкладка

1. Скопировать `photo-service/assets/pedestrian-paths/` на сервер в
   `/opt/sao-photo-service/photo-service/assets/pedestrian-paths/`.
2. Пересобрать службу:
   `docker compose -p sao-photo-service -f compose.yaml -f compose.recovery.yaml build photo-service`
   и `up -d photo-service`.
3. Применить миграцию: `docker compose ... exec -T photo-service node scripts/migrate.js`.
4. Импортировать точки:
   `docker compose ... exec -T photo-service node scripts/import-pedestrian-path-points.js --source=assets/pedestrian-paths/points.geojson --apply`.

Повторный импорт обновляет координаты и адреса по `point_no`, не меняя id и номера.
Исчезнувшие точки снимаются только если у них нет фото.
